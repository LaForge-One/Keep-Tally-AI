# Documentation Quality Checklist

Generated: 2026-05-30

Use this checklist before treating a document as ready for review or record keeping.

## Required Checks

- Read the document once for technical accuracy.
- Read the document again for spelling, grammar, and clarity.
- Confirm headings use consistent capitalization.
- Confirm acronyms are used consistently, such as API, CSV, DB, VPS, and AI.
- Confirm commands are fenced as `bash`, `sql`, `text`, or another appropriate language.
- Confirm code paths and filenames are wrapped in backticks or linked when appropriate.
- Confirm diagrams render as valid Mermaid syntax.
- Confirm no secrets, passwords, tokens, or private URLs are included.
- Confirm test-environment wording is accurate and does not describe VPS testing as production.
- Confirm recommendations are clearly separated from implemented changes.

## Style Preferences

- Keep sentences direct.
- Prefer active voice.
- Avoid unnecessary filler.
- Use consistent terms:
  - `VPS test environment`
  - `admin user`
  - `account membership`
  - `location assignment`
  - `store inventory`
  - `warehouse inventory`
- Use `preflight` consistently as one word.
- Use `login` as a noun or adjective and `log in` as a verb.

## Final Review Note

The local environment does not currently include a dedicated spellcheck utility. Until one is added, documentation should receive a manual proofreading pass before handoff.
