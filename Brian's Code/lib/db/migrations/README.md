# KeepTally Database Migrations

## Baseline Warning

`0000_baseline.sql` is for brand-new, empty databases only.

Do not run this baseline migration against an existing Replit, staging, or production database that already contains KeepTally tables. It uses `CREATE TABLE` statements and will fail when those tables already exist.

## Existing Database Adoption

Before adopting migrations for an existing database:

1. Back up the database.
2. Dump the current database schema.
3. Compare the live schema against `0000_baseline.sql`.
4. Resolve any schema drift explicitly.
5. Only after confirming equivalence, mark the baseline as applied using the deployment platform's approved migration-journal process.
6. Run future migrations normally after the baseline is adopted.

Do not use `drizzle-kit push` as the production migration path once migrations are adopted.

## Generating Future Migrations

Use Drizzle Kit from a normal pnpm environment:

```sh
pnpm install --frozen-lockfile
pnpm run db:generate
pnpm run db:check
```

Then review the generated SQL before applying it.

## Applying Migrations

Only apply migrations after backups are confirmed:

```sh
DATABASE_URL=postgresql://... pnpm run db:migrate
```

## Metadata Note

Migration metadata should be generated by Drizzle Kit. If metadata is edited manually or a generation command cannot be run locally, regenerate it in a verified pnpm environment before enabling migration checks as a blocking CI step.
